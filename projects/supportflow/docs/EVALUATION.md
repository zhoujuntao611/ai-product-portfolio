## 指标定义

**路由完全匹配**：实际 `status` 与人工列出的 `expected_status` 相同的案例数 / 全部案例数。这里只验证有限路由样例。

**召回文档集合完全匹配**：实际召回编号集合与 `expected_sources` 完全一致的案例数 / 全部案例数。命中额外无关文档也记为失败。该指标不评价语义充分性，也不衡量大规模检索能力。

**事实条目原文/引用一致性**：有事实条目的案例中，所有条目编号存在于有效知识库、文本与对应原文完全相等、引用出现在草稿中且来源在召回结果中的案例数 / 含事实条目的案例数。拒答无条目案例不作为成功分母。该约束由系统原文组装实现，不等同于模型幻觉测量。

**整例通过**：路由、文档集合、引用约束、必需片段、禁用片段、归档过滤、无事实要求和有限脱敏要求全部通过。

**本地处理时间**：进程中单次 `generate` 的壁钟耗时。报告给出 median/max，主要反映小型 Python 规则/检索处理；不包含网络、浏览器、客服人工或真实模型耗时。不要据此声称模型性能提升或节省业务工时。

## 样例范围

正常案例包括发票、登录、两地区退款、数据导出、Webhook、限流、订阅到期、故障与多意图。异常案例包括未知地区、正文/下拉矛盾、企业合同、归档版本、不存在的产品能力、已知/未知混合、有限注入样例、隐私隐藏、高影响操作与未经核验承诺。

工程测试另覆盖：生成/读取/批准及 SQLite 持久化、重复审核、缺少证据禁止批准、转人工、人工修改标记、正文大小、JSON 类型、CSRF、恶意 Origin、无效 Host、静态路径白名单与 CSP。

## 模型适配器验证与真实模型的区别

模型适配器使用模拟响应验证：合法编号、输入基础脱敏、未知文档、非候选来源、将伪造事实当编号、格式错误、截断、空证据、超时、HTTP 错误不回显密钥、非 HTTPS 配置及风险工单不调用模型。

模拟数据证明代码遵守接口约束，不能证明真实服务正常联通或模型理解质量。报告没有模型成功率、真实 token 成本或真实模型响应时间。

## 已知局限与下一步

- 风险正则仅覆盖列出的有限攻击形态。改写、编码、多语种和语义隐藏可能绕过，不能当作通用注入检测器。
- 模型只能选已有条目，但依然可能选错主题、漏选限制条款；引用真实不等于答案正确。
- 关键词检索在同义表达、错别字、长工单、多问题和新业务主题上可能漏召回；最多 4 份文档也会截断复杂问题。
- 合成政策准确性来自人为构造；没有真实政策更新、合同例外或权限数据。
- 基础脱敏不是完整 PII 检测；真实模型验证只能用获授权的脱敏数据。

建议后续冻结一份 100 条未参与开发的工单集，由两人分别标注；按正常/冲突/缺失/攻击/高影响分层。先测纯人工检索基线与规则版，再测可配置模型版。记录模型 ID、日期、提示版本、价格来源和错误样本；引用准确率与事实正确性需分开评分。若测试发现错误，将样例作为回归集但从盲测集移出，防止把学习过的样例继续当独立效果证明。
