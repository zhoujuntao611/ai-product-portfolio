## 分项检查与分母

- **路由正确**：v1 35/60，v2 60/60。逐题比较明确列出的 ready、needs_context、conflict、unknown、escalate、refused。
- **检索文档集合完全一致**：49/60 → 60/60。遗漏或多召回均失败；候选检索和最终回答支持分别计分。
- **已输出事实的政策适用性**：39/42 → 31/31。核对当前版本、启用状态、有效期和地区，不将无事实回答算入分母。
- **已输出事实的原文与引用一致性**：42/42 → 31/31。编号、原文、引用格式和来源版本一致；v1 没有逐条版本字段时核对其来源快照版本。
- **已输出事实的回答支持检查**：22/42 → 31/31。除引用与适用性外，检查题目的应答状态、人工指定的来源、必要事实和限制条件；需要澄清的题若直接输出政策事实视为失败。
- **澄清正确**：4/20 → 20/20，分母只包括预期 needs_context/conflict 的题。
- **人工处理路径正确**：4/6 → 6/6，分母只包括预期 unknown/escalate 的题；refused 单独纳入总路由检查。

两版输出事实的案例数量不同，因为 v2 对资料不足、冲突和错选依据停止生成。报告保留各自分母，不把未回答案例当作“引用支持成功”。ready 却没有可核对条目的结果直接失败。

“支持检查”是对固定题人工指定答案要求的自动验收，不是通用语义蕴含评分。评测脚本独立核对引用和元数据，不使用引擎自己的 passed 标记作为正确答案；另有测试主动篡改版本、引用和条目，验证评测能发现错误。

## 失败原因与修复

S01–S06：同义问法没有原关键词，v1 漏召回；同义配置修复主题准入。

M01–M04：多个问题只命中部分主题、未知问题被已知主题掩盖、全局 top 4 截断；逐问题检索和覆盖检查修复。

R01–R02、P01–P08：地区不明确、同时提到两个地区、过期/未生效、冲突政策，以及把独立数值误当同一事项；元数据和冲突门限修复。

E01–E05：存在的引用回答了错误维度，或遗漏第二问及独立限制；按入口、时效、数量、有效期和限制条款检查支持。

U01–U03：同主题未知属性被当成已有能力，例如纸质发票邮寄、导出已删除记录、恢复误删；增加所问属性与动作的依据检查，停止事实草稿。

工程测试还固定同文档内冲突、中文数值、许可矛盾、不同事项不误报、跨日失效、旧草稿批准拦截、超长条款转人工、中文编辑容量、非 ASCII 请求校验、审核轨迹与脱敏导出等边界。

## 模型接口与尚未测量部分

沿用原 HTTPS `/chat/completions` 接口。模拟响应覆盖合法/非法编号、非候选条目、错误 JSON、截断、空证据、超时、错误响应、凭据不回显和输入基础脱敏。无密钥环境已完成规则运行与协议验证。

尚未测量：真实供应商联通、模型理解与选证质量、真实 token 成本及响应时间、客服采纳率、节省工时和客户满意度。当前检索、属性支持与冲突识别仍为可解释规则；下一轮用授权脱敏资料，冻结未参与修改的测试集，分别标注适用性、条款支持、澄清和人工路径。
