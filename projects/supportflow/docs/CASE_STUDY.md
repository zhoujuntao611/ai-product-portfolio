# SupportFlow 项目案例

## 项目定位

面向一线客服和政策维护者的 AI 回复审核工作区，将“找政策、确认适用、整理草稿、人工审核、回收问题”串成可运行流程。使用者可以导入自己的政策，而不是只能体验内置问答。

## 产品判断

迭代中最关键的问题是“命中资料”与“可以回答”之间存在差距。将优先级放在知识生命周期、逐问题覆盖和引用支持，沿用原应用及模型接口，把质量问题变成可定位、可复现、可回收的产品对象。

选择结构化 JSON 降低政策接入成本并明确元数据；用同义扩展和逐问题检索覆盖常见表述；将版本、地区、生效时间和条款支持设为生成及审核门槛。保留人工编辑、问题原因和来源版本，使每轮评测有可追溯输入。

## 已交付成果

- 知识治理：资料导入、字段校验、版本替换、停用和历史维护。
- 回复质量：按问题检索、逐条引用、适用性与支持检查、澄清及人工处理。
- 反馈闭环：编辑审核轨迹、结构化问题原因、脱敏样例导出。
- 验收证据：同一套 60 道合成开发题整例通过 33/60 → 60/60；2026-10-19 新增审阅回归 14/26 → 26/26，118 项工程测试通过。浏览器报告按实际执行日期保存，逐题结果、基线和失败样例随代码保留。

## 2026-10-19 审阅与修复

发现地区常见表述漏识别，以及“时间数字存在”无法证明退款到账、审批或导出生成时效；每月额度也不能用每分钟速率直接作答。比较继续放宽关键词、增加可解释事项门槛和模型判定后，先统一地区推断/矛盾检测，并对实际选中条款核对所问事项及周期。已保留问题输入、冻结修复前代码、方案理由和逐题结果，详见 [完整证据链](ITERATION_EVIDENCE.md)。

人工转交和拒绝时的编辑稿保存、原子导入和政策更新拦旧稿，在本地 v2.0 已经通过；本轮重新验证，不计为新修复成果。
