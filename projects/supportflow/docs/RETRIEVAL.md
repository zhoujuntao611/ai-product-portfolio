# 检索与证据支持：从 v1 到 v2

## 原方案已完成什么

v1 按 `keywords` 字面命中数排序，过滤停用和晚于知识快照的资料，按地区筛选后最多召回 4 份文档。规则模式摘录全部候选条款；可选模型只选择已有条目编号。已有逐条引用、地区退款澄清、人工审核和本地状态保存。

冻结实现、原知识及报告保存在 `eval/baseline_v1_*`，来源为仓库提交 `5aef4cc`。只调整冻结文件的资源路径，没有改写原算法。

## 真实问法暴露的问题

- **同义表达漏召回**：“报销凭证在哪里开具”“接口被节流”不含原关键词，v1 找不到政策。
- **一个命中掩盖多个问题**：“发票如何申请，是否支持离线编辑”会让已知问题的资料掩盖未知问题；五个主题还会被全局 top 4 截断。
- **来源有效但不适用**：地区未知、自导地区资料、有效期结束、同范围条款冲突需要独立处理，不能只看文档是否启用。
- **引用存在但没有回答问题**：询问下载链接有效期时，选择“50,000 行”的原文，编号真实却不支持答案。只选开票入口也不能回答开票时效。
- **主题相关但属性未知**：开票政策不等于支持邮寄纸质发票，数据导出政策不等于包含已删除记录。

逐题的输入、预期、双方草稿与引用见 [comparison_v2.json](../eval/comparison_v2.json)；失败样例单独保留在 [failure_cases_v2.json](../eval/failure_cases_v2.json)。

## 比较后选择的方案

继续使用本地词法检索，增加**可维护同义表达、逐问题拆分、BM25 排序、元数据过滤和支持检查**。不引入新服务或模型密钥，直接复用当前 Python 应用。

同义表达配置有独立版本，位于 [retrieval_config.json](../data/retrieval_config.json)。主题识别同时使用用户资料的关键词，因此新增主题不必先修改代码。泛词如“保留”不会盖过明确的“导出”主题。

文档以英文词及中文双字片段建立 BM25 词频分数，参数为 `k1=1.2`、`b=0.75`，加上关键词命中分。关键词和同义词决定候选准入，BM25 用于排序；本版没有证明 BM25 单独带来多少收益，也不将该实现称为向量语义检索。

每个问题分别识别主题并保留候选，避免全局 4 份上限截断。先按地区、当前版本、启用状态、生效与失效日期过滤；正文多个地区或与选择项矛盾时要求确认。候选内同一事项的时间、数量或许可冲突会阻断生成，交由政策负责人更新资料。

另一条可行路线是向量召回加重排，可能改善未列入同义词的改写，但需要额外模型、索引维护、成本和跨版本评测。当前知识规模小，主要错误可以通过资料治理、分问题检索和明确支持门限定位，先把这条闭环做完整。后续在授权脱敏长工单上比较召回率和相关性，再决定是否引入向量索引。

## 引用与支持如何检查

1. **溯源一致性**：条目编号、引用格式、完整原文和来源版本必须一致。
2. **政策适用性**：资料必须当前有效，地区明确适用；旧版、停用、待生效和过期资料不参与回答。
3. **问题支持与覆盖**：每个问题都需有候选和所选条款；入口、时间、数量、链接有效期、签名密钥等检查对应事实维度。问限制条件时，不得遗漏独立限制条款。对已知主题里的新能力或属性，检查资料是否覆盖所问内容。
4. **可处理的草稿**：资料不足、冲突或支持不全时停止事实草稿，给出澄清或人工处理路径。条款过长超出审核容量时改为简短转人工草稿。

模型接口仍为原 `POST /chat/completions` 证据编号选择，本地执行相同的支持检查。人工修改保存为编辑稿，原稿的验证结果不会被当成人工新增内容已验证。

这是一组可解释的规则门限，尚未测量开放域语义蕴含或任意政策冲突的识别效果。完整原文可保留条款条件，但资料本身的正确性仍由维护者负责。

## 借鉴成熟客服产品的流程

Intercom Fin 将上下文澄清与内容来源指引设为不同配置，并提供版本历史；本项目据此把“先确认适用范围”和“选择哪份资料”拆开处理。[Intercom 官方说明](https://www.intercom.com/help/en/articles/10210126-provide-fin-ai-agent-with-specific-guidance)

Intercom 的测试流程允许查看低质量回答的原因及来源；SupportFlow 将这一做法落到可操作的审核原因、来源版本与导出样例。[Intercom 测试与部署说明](https://www.intercom.com/help/en/articles/8286630-deploy-fin-ai-agent-over-chat)

Zendesk 的生成回复流程收集用户反馈；本项目先实现审核者的结构化反馈与问题回收，使下一轮评测有输入。[Zendesk 官方说明](https://support.zendesk.com/hc/en-us/articles/6138268212634-Using-AI-to-generate-replies-in-an-AI-agent-for-messaging-Legacy)

以上用于参考交互与产品机制，未移植其专有检索技术或引用其效果作为本项目成果。
