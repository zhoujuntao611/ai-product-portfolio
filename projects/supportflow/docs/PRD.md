# SupportFlow 产品需求说明 · MVP v1.0

## 问题与用户假设

假设目标用户是一线 SaaS 客服，他们处理重复咨询时需要在多份政策中找答案，并核对版本与地区。知识分散可能导致引用过期政策，直接生成可能导致不适用的承诺。此假设来自产品场景推演，**未开展真实访谈或客户数据分析**。

价值主张：让客服先看到可检查的来源，再获得草稿，保留人工决定权。作品集展示从问题定义、范围取舍、异常路径到验收与评测的产品工作。

拟验证方式：招募 5–8 名有 SaaS 客服经验的受访者，问他们最近一次查政策的具体过程、如何识别过期条款、哪些回复必须升级审批。使用经授权脱敏的 50–100 条历史工单，观察找来源步骤与草稿审核过程。受访人数及历史数据均为计划，不是已发生事实。

## MVP 范围与优先级

P0：输入 5–4000 字工单；显式地区上下文；仅召回有效政策；区分有据可答/缺少信息/地区冲突/风险请求/高影响请求/知识未覆盖；回复中逐条引用；生成、人工批准/拒绝/升级的完整状态机；SQLite 持久化；可见演示模式标识。

P1：版本清单、人工修改标记、审核备注、历史记录、带来源 Markdown 导出、可选模型证据选择、接口异常可解释反馈。

不纳入当前版：真实客服系统接入、自动发送、身份授权校验、资金或账号操作、文件上传、向量索引、企业权限、多租户、批量处理与生产部署。

## 使用路径与状态

输入工单及地区 → 基础格式隐藏 → 风险/上下文路由与有效文档检索 → 证据摘录或停止作答 → `DRAFT` 保存 → 人工审核。

批准只允许 `ready` 的 `DRAFT` 工单转成 `APPROVED_LOCAL`，并且前端要求勾选检查项。未知、冲突、缺少信息、拒答、高影响状态禁止直接批准；可以转成 `ESCALATED` 或 `REJECTED`。已完成审核的记录不能再次批准；更新信息后需新建工单。

后端限制以证据状态和持久化状态为准，勾选框是本地审核交互，不是身份认证。所有状态均不触发外部发送。

人工编辑后显示“未自动验证”，审计记录保存 `human_edited`、`automatically_validated` 和内容指纹。SHA-256 能对比内容变化，但没有日志签名或独立可信存储，不能称为不可篡改审计。

## 证据与生成策略

文档按编号、版本、更新时间、地区、有效状态治理。知识快照固定为 2026-10-13；已归档或晚于快照的文档不参与检索。关键词匹配并按命中数排序，最多返回 4 份候选文档；不是语义向量检索。

地区未知退款同时命中两份不同窗口的政策时，要求澄清；不得把 7 天和 14 天合成一个统一政策。正文地区与 UI 地区矛盾时停止作答。企业定制合同需要人工核验。有限列举的已知+未知混合主题会要求拆分；其他多主题问题必须人工检查完整性。

默认规则引擎输出检索原文及 `[KB-xxx §n]` 引用。可选模型只从候选原文中选择条目编号；验证编号合法后继续使用原文。因此模型可以选择不够相关或不完整的条目，但不能直接引入任意生成政策。这一取舍优先展示可核验性，牺牲自然措辞与精细问答能力。

## 核心验收标准

1. 默认发票问题只召回 `KB-002`，草稿包含准确开票入口、3 个工作日说明及逐条引用。
2. 大陆/海外标准退款问题分别仅召回适用文档。地区未知时呈现政策冲突，禁止批准。
3. 归档 `KB-010` 不能作为当前退款依据；界面可查看它的归档状态。
4. 知识未覆盖问题不生成事实性能力承诺；高影响请求不得执行账户或资金操作。
5. 对已列出的风险样例拒答；风险规则的局限必须可见，不把回归样例通过率当安全保证。
6. 草稿批准后，刷新仍能读取最终文本与两次状态事件。重复审核会返回错误。
7. 修改草稿显示未自动验证，批准事件保存人工修改标记。
8. 缺少密钥时禁用真实模型模式；模型格式异常、未知来源、截断、超时、错误响应不显示凭据，且不会静默伪装成功。
9. 请求大小限制、静态文件白名单、Host/Origin/CSRF 验证工作；浏览器文本用 textContent 呈现，禁止执行来源文档中的指令。
10. 前端在窄屏可使用；错误、等待与完成反馈可见；敏感输入只用演示数据。

## 指标与验证计划

已测工程指标：合成案例路由完全匹配、召回文档集合完全匹配、事实条目原文/引用一致、状态持久化与异常接口契约。完整定义见 EVALUATION.md。

计划业务指标：客服审核后采纳率、一次解决率、查政策到合格草稿的时间、升级率、风险误放行率。采纳率必须区分原样采用/小改/重写，时间需与人工检索基线比较；未取得真实数据前不报告收益。

真实模型验证需要明确提供商、模型版本、样例集、提示模板和成本记录，再由两位标注者评价相关性、完整性、政策适用性与引用正确性。当前没有真实模型测量。

## 风险与迭代

P0 风险是把不适用政策写进回复。当前通过有效版本、地区澄清与人工审阅缓解，仍不能识别所有上下文；下一步应增加合同/订阅类型和政策生效区间。

关键词检索容易漏召回与过召回，应先引入人工标注样例和错误分析，再考虑混合检索与重排序，不能把加向量库当作已证实的质量提升。正则风险识别可能被变体绕过，应加入权限边界、外部动作的独立授权、攻击集和注入上下文隔离；当前工具没有外部动作权限。

基础脱敏只覆盖常见邮箱、手机号与明确标识的密钥，不保证发现所有个人信息。数据库未加密、没有用户权限；当前适合本机虚构数据展示。生产接入需要授权、隐私评估、访问控制、数据保留机制、审计防篡改和回滚，不属于本次 MVP 已完成能力。
