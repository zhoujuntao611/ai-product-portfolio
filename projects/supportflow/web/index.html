PRODUCT CASE STUDY

一个可以解释决策的 AI 产品原型。

从问题定义到证据策略，再到验收与评测。

产品假设

知识分散、政策变化与重复问题可能增加客服回复成本。这是尚未经过真实用户访谈验证的假设。

目标用户是处理重复工单的一线客服。MVP 聚焦起草与审核，不处理支付、删除或外部发送。

实现边界

Python 标准库、SQLite 与原生网页。默认关键词检索 + 规则路由 + 原文摘录；不是向量检索或自主 Agent。

可选真实模型只选择已有证据条目，回复仍使用知识原文。未提供密钥时不调用模型，也不会显示模型效果数据。

质量验证

项目包含独立列出的合成工单案例、离线评估脚本、服务接口测试和评估报告。评估验证工程行为，不代表真实客服效果。

真实模型质量、实际采纳率、节省工时与用户满意度尚未测量。请阅读项目 docs/EVALUATION.md。

产品体验路径

先展示有据可答的发票问题，再展示地区未知的退款问题和不安全请求，最后打开审核记录。

体验时可核对：停止作答的条件、人工确认后的状态变化，以及草稿与有效版本的引用关系。
