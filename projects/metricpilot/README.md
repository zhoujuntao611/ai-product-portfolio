# MetricPilot · 订单分析

面向运营人员，解决订单分析口径不一致、结果难复核的问题。

导入一张订单 CSV，确认日期、字段和退款口径，再计算收入、渠道与退款指标。当前入口采用规则解析与受约束计算。

开发时最主要的错误是口径冲突：问题要求按退款发生日统计，界面却选择了订单日。现在遇到这种冲突会暂停查询，等用户修改。首版聚焦单表收入、渠道和退款分析，每项结果都保留计算条件与源行引用。

界面使用横向导航，条件放在报表上方。查询成功后折叠条件，可以展开修改；数据、计算口径和源行引用随报告保存。

## 启动与体验

需要 Python 3.10+，仅使用标准库，无需安装依赖。在本目录运行：

```powershell
python app.py
```

打开 [本机工作台](http://127.0.0.1:8766)。指定端口：`python app.py --port 8866`；停止服务使用 Ctrl+C。

1. 上传订单 CSV，或下载 [示例模板](templates/orders-template.csv)。每笔订单一行，最多 2 MB、10,000 行、50 列。
2. 预览数据并确认字段映射、日期格式、金额单位及币种。重复、缺失和格式问题会显示处理选项；检查通过后才导入。
3. 确认退款按订单日还是退款发生日归属，选择取消订单处理方式；排除取消订单时填写源表的精确状态值。
4. 输入有明确期间和指标的问题，查看收入概览、渠道比较或退款分析。点击 Q 引用复核筛选、参数、原始聚合结果和源行号。
5. 导出 Markdown 或 JSON 报告，保留指标说明、处理决定和查询证据。

可使用模板尝试：

- “2026年1月净收入是多少？”
- “2026年1月各渠道毛收入比较”
- “2026年1月退款金额占毛收入比例”
- “2026年2月对比2026年1月净收入变化”
- “2026年1月退款率”会先询问分母。

## 解决的三类任务

**收入概览**同时核对毛收入、退款、净收入与订单数，避免把表内净额解释为利润或到账金额。

**渠道比较**按源表渠道分组，并查询同条件总览复核金额与订单数。退款占比按各组分子、分母重新计算，不平均各渠道百分比。

**退款分析**分别提供退款金额占比与退款订单占比，并明确退款日期归属。选择退款发生日时，跨期退款可能让占比超过 100%；报告保留该口径。

未映射退款金额时，退款与净收入保留未知；只有明确确认“所有订单无退款”才填 0。没有渠道列则关闭渠道分析；没有状态列时明确说明无法识别取消订单。

## 产品范围与计算方式

支持一张、一订单一行的 CSV，使用明确的期间、主指标和渠道筛选。输入缺期间、分母或与筛选冲突时先澄清。商品明细、多次退款流水、多币种混表需要先在源系统整理为本工具支持的结构。

六项核心指标为毛收入、净收入、退款金额、订单数、退款金额占比和退款订单占比。这些指标可从订单金额、退款金额和订单标识逐项核对。详见 [指标说明](docs/METRICS.md) 和 [产品决策](docs/PRD.md)。

计算通过 `query_orders(period, dimension, channel)` 完成。工具只接受受约束参数，由应用生成参数化 SQL；查询阶段使用 SQLite 只读限制和访问白名单。没有任意 SQL 接口，旧 `/api/sql` 已移除。

v2 使用本机确定性问题解析与统计工具，无外部模型请求，外部模型调用费用为 0。旧合成数据和模型协议代码保留在 `legacy.py`，用于离线回归，不接入当前产品路由。

## 结果如何复核

每次运行记录数据集、源文件 SHA-256、字段映射、导入处理决定、分析口径与耗时。结论和结果行引用本次 Q 编号；查询证据包含工具参数、筛选条件、SQL、绑定值、原始聚合结果及 CSV 物理行号。金额以币种最小单位整数计算，日期起止均包含。

归一化订单与最近 40 次分析记录保存在本机 `data/`，可用 `METRICPILOT_DATA_DIR` 指定目录。导入草稿保存在进程内存，重启后重新上传；请保留源 CSV 以便按行号复核。
