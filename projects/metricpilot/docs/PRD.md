# MetricPilot 产品需求 · v2

版本日期：2026-10-18。目标是让一份订单导出表直接进入可复核的收入、渠道与退款分析。

## 目标用户与价值

面向需要从订单表整理经营简报的运营、产品经理和小团队负责人。用户准备一份 CSV、确认业务口径，即可得到统计结果和随时可核对的报告。

本次交付的产品成果是把固定数据演示升级为“数据接入 → 质量检查 → 口径确认 → 只读查询 → 证据报告”的可运行闭环。产品能力以代码、独立夹具和验证记录支撑。

## 首版范围

只处理一张订单 CSV，每笔订单一行。必需字段为订单标识、订单日期、退款前金额；可选退款金额、退款日期、渠道、状态和币种。单文件限 2 MB、10,000 行和 50 列。

优先支持三类任务：

1. 收入概览：指定期间的毛收入、净收入、退款和订单数。
2. 渠道比较：同一期间、同一口径下的渠道金额、订单数与退款占比。
3. 退款分析：明确金额或订单分母，选择按原订单日或退款发生日归属。

支持两个明确期间的比较；一次选择一个主指标、一种分组。跨表连接、商品明细汇总、多次退款事件、汇率换算、自定义指标和通用 BI 不进入首版。

## 用户流程

上传 → 预览前 12 行和字段建议 → 手动映射 → 选择日期格式、币种、金额单位 → 查看检查结果 → 选择处理方式并复查 → 导入 → 确认分析口径 → 提问或选定筛选 → 查看报告、引用和原始返回 → 导出。

导入建议不直接成为最终处理决定。完全重复行可显式删除；缺失退款可显式填 0；空渠道可显式标为“未标注”；普通异常行可显式排除。订单标识冲突、多币种及不规则 CSV 结构需修正来源或拆分，不能通过排除选项绕过。

没有退款列时先把相关指标设为未知；用户明确确认全表无退款后才记 0。没有渠道列则不提供渠道分组；没有状态列则显示取消状态不可识别。

## 指标与查询决策

选择毛收入与净收入，便于对照“订单金额”和“扣除退款后的净额”；保留退款金额，便于复核两者差额。选择订单数作为业务规模与订单退款分母。将退款金额占比和退款订单占比分开，避免同名“退款率”对应不同结论。

所有分母由同一查询范围计算。渠道百分比不能直接平均；跨期退款按发生日统计时，分子与分母来自不同订单集合，允许超过 100%。完整定义见 [METRICS.md](METRICS.md)。

使用参数化的 `query_orders` 工具，参数限制为明确期间、总览或渠道分组、可选渠道值。应用构建 SQL 并在只读查询环境执行，避免自然语言直接变为任意 SQL。问题解析负责识别或澄清条件；结论由已执行的结果生成。

只输出表内可统计的事实。渠道金额较高不能证明渠道效率较高；收入变化不能自动归因为投放或用户行为。

## 口径契约

分析前确认：

- 退款归属原订单日，还是退款发生日。
- 保留或排除取消订单；排除时由用户提供源状态列的精确值，区分大小写和空格。
- 导入金额单位和币种；日期粒度为天，起止日均包含。

期间、分母不明确时先澄清；问题与界面筛选或退款日期归属冲突时要求统一；混合季度、月份和完整日期比较先要求统一输入，不保留部分条件执行。显式未知分母不代换成毛收入。缺少所需字段时说明如何补齐。首版用重新提交补充信息。

本轮需求决策、候选方案与实际修复前后结果见 [2026-10-19 迭代记录](ITERATION-20261019.md)。

## 报告与证据

每个结论和结果行关联本次 Q 引用。查询证据保留工具参数、筛选、SQL、绑定值、原始聚合结果、源文件 SHA-256 与 CSV 物理行号；导出保留口径、字段映射和处理决定。

文件指纹用于识别具体输入，源行号用于定位参与计算的订单。导出物让其他人能够按同一输入与同一口径重新核对结果。

## 验收与验证

使用独立手工构造的 9 笔订单，覆盖月初月末、跨月退款、部分与全额退款、零金额、取消状态和分级金额精度。分别验证金额、分子分母、日期闭区间、渠道加总和退款发生日口径。

补充重复行、冲突订单、缺失值、非法日期、非法金额、币种混用、非矩形 CSV、文件限制和含糊问题。关键问题理解失败保留首次失败记录及修复后用例。运行方式和实际结果见 [README](../README.md) 与 [eval_report.json](eval_report.json)。

v2 无外部模型调用，模型费用为 0。未来接入真实模型时，应固定相同任务集，分开报告问题理解、工具参数、数字、引用的正确性，以及耗时、供应商实际费用和失败原因；不以本机规则回归代替该评测。
