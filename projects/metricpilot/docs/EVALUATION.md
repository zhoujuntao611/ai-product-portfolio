# 评测方法与结果解释

执行入口：`python evaluate.py`。运行后同时生成根目录和 `docs/` 中的 `eval_report.json`，记录实际时间、运行数量、失败、分组和每个案例的状态。报告不是手填统计；出现失败时脚本退出码为 1。

## 样本与期待值

数字验证使用独立的 4 笔手工订单，包含全额退款、部分退款、无退款和月份边界。9 月：2 席 × 100 元无退款；3 席 × 200 元退款 100 元；1 席 × 100 元全退。期待值为毛收入 900 元、退款 200 元、净收入 700 元、3 笔订单、6 席位、2 笔退款订单。8 月另有 1 笔 200 元无退款订单。期待值直接写在测试中，不由业务查询函数回算。

合成库验证检查 2,457 笔、日期边界，以及 9 月 270 笔和 420,008.50 元净收入。分组可加总指标与独立总览比较；比例不做简单相加。空范围金额为零、零分母比率为缺失；月份对比给出 250% 相对变化，退款比率比较以百分点表达。

## 离线回归的分类

当前测试集合包含 **72 条回归检查**，不是 72 个真实用户或真实模型业务任务：

- 数值和业务域：23 条，验证独立金额、计数、分母、分组、日期、引用及合成库。
- 澄清和输入：14 条，验证日期/口径歧义、越界、多指标和明确筛选。
- SQL 守卫和资源：16 条，验证写操作、附加库、系统表、多语句、危险函数、递归、行数和执行限制。
- 模型协议本地桩：11 条，验证工具调用、逆序/分步返回、重复调用、错误参数、畸形参数、幻觉文字、超时、无配置、不安全接口和不跟随重定向。
- 本机 HTTP 边界：8 条，验证健康识别、Host、Origin、CSRF、JSON、实际分析/会话，以及 HTTP SQL 写拦截。

以最新 `eval_report.json` 的实际 passed/failed 为准。部分测试是边界/安全测试，不能把总通过率当模型回答准确率。

## 未验证项

未对任何真实外部模型进行在线评测，未收集真实用户使用样本，未做生产压力和多租户访问测试。默认规则模式只覆盖文档列出的语法，不评估通用语言理解。合成退款公式不存在真实趋势和因果关系，因此不能推导商业效果。

本地 HTTP 桩是协议验证：它根据预置响应返回标准工具调用，可证明应用将工具结果送回模型、校验范围并限制步数；它不会证明供应商兼容性、模型规划质量或稳定性。

## 下一步评测设计

若用户自行配置真实模型，先冻结一组人工标注任务与模型版本，分别记录计划正确、数字正确、期间/分母正确、引用正确、正确澄清、正确拒绝、工具步数、时延和 usage 成本。保留全部失败样本，按漏澄清、错误范围、工具错误、数字不一致等分类。供应商层的失败单独报告，不能丢弃后只展示成功比例。任务成功的定义应要求全部质量条件满足，而不是模型给出一段流畅答案。
