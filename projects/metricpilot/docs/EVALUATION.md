# MetricPilot v2 验证与复核

运行 `python evaluate.py` 验证导入、数值、澄清、工具和 HTTP；运行 `python evaluate_tasks.py` 重放固定业务任务。结果分别写入 [eval_report.json](eval_report.json) 和 [task_report.json](task_report.json)。失败会返回非零退出码。

## 独立手算数据

[9 笔订单夹具](../tests/fixtures/hand-check-orders.csv)覆盖跨年、月初月末、跨月退款、全退、部分退款、取消、零金额、0.10 与 0.20。期待值直接写入测试，不用同一个查询函数生成答案。

- 1 月排除 `cancelled`、按订单日：毛收入 350.00，退款 120.00，净收入 230.00，3 笔订单，3 笔退款订单。退款金额占比 120/350，退款订单占比 3/3。
- 1 月渠道净收入：organic 80.00，paid 150.00；分组金额和订单数必须等于独立总览。比例按合计分子分母重新计算，不相加、不简单平均。
- 2 月按订单日：毛收入 120.10，退款 30.00，净收入 90.10，3 笔订单、1 笔退款订单。
- 2 月按退款发生日：毛收入 120.10，退款 120.00，净收入 0.10；退款订单 4 笔 / 下单订单 3 笔 = 133.33%。这说明跨期事件口径不能解释为队列退款概率。
- 仅有退款而无下单的日期允许净收入为负；零分母显示不可计算。起止日均包含当天。

## 回归范围

CSV 检查覆盖字段映射、完全重复与冲突订单号、缺失退款、异常行排除记录、多币种、日期歧义、时间戳、负数、非有限数、超额退款、非法精度、整数溢出、JPY 单位、文件和行列上限。不能用“排除异常行”绕过结构冲突和多币种。

问题理解覆盖缺期间、缺年份、相对日期、退款分母、问题与筛选冲突、指定渠道、多个分母、月份区间、多个季度和缺失字段。澄清时查询数为零。工具仅接受日期、渠道和两个枚举分组，拒绝任意 SQL 与未知参数。

HTTP 验证完整导入到报告流程、模板下载、来源预览、分析记录、数据路径、Host/Origin/CSRF 和静态文件。主服务启动不生成固定合成库，`/api/sql` 已移除。

原 v1 的 72 项检查保留在 `legacy.py` 与 `tests/test_metricpilot.py`，报告分组以 `legacy_` 标明；用于原有数值、只读 SQL 守卫和本地模型协议回归，按历史 v1 分组报告。

## 固定任务与后续模型评估

[eval/tasks.json](../eval/tasks.json)保存相同的二十四个任务及独立期待值；`task_report.json` 逐项报告问题理解、工具参数、数字、引用、耗时、外部调用成本与失败原因。当前执行的是本机规则与统计引擎，外部模型调用和费用均为零。

2026-10-19 补充冻结代码重放：22 个自建验收任务由 11/22，经第一次修复 17/22，最终变为 22/22；11 个失败样例已澄清且不执行查询。第一次修复只检查分母前缀，独立复核发现运算分母仍被替换；最终匹配完整分母及允许的语气后缀，并保留标准问法正控。当前 CSV v2 回归 90/90 与历史 v1 回归 72/72 分开统计；固定任务 24/24 与回归及重放存在重叠，各套件分别报告。问题、方案与修复过程见 [本轮迭代记录](ITERATION-20261019.md)。

如后续验证真实模型，应冻结该任务文件和 CSV 的 SHA-256，另存模型标识、版本、提示、采样设置和供应商 usage，不覆盖离线报告。问题理解以期间/指标/渠道和澄清决策评分；工具参数以允许范围、日期、渠道、口径评分；数字按独立期待值评分；引用核对本次查询、筛选和原始返回。逐任务记录总耗时、模型耗时、tokens、实际价格及币种；没有 usage 或价格时费用填未知。超时、无效参数、缺工具、错误澄清和引用错位分别记失败原因；模型实际运行结果单独保存。

浏览器验收脚本和截图保存在 `verification/`，使用明确标注的手算夹具。运行需要安装 Playwright 和本机 Chromium/Edge；应用本身无需这些依赖。
