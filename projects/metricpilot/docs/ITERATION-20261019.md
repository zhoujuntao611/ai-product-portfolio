# MetricPilot：问题、取舍与验证记录（2026-10-19）

本记录说明真实完成的工程迭代。问题来源是代码审阅和自建业务验收任务，没有进行用户访谈、线上 A/B 实验或真实模型评测。本版使用确定性解析和受约束计算；AI 协作参与分析、修改与回归执行。本文不证明候选人个人独立完成了每一步。

## 1. 从什么问题出发

原先固定合成数据只能展示分析流程，使用者不能放入自己的订单表。10 月 18 日的 CSV v2 已加入导入、映射、数据质量检查、退款口径、查询证据与报告导出。这些是已有成果，不能写成本轮新增。

10 月 19 日先重验旧审阅的净收入分母、多渠道、多产品、双季度及多主指标五类问题。新版均已进入澄清，说明旧审阅结论不应直接套用到 v2。随后用同一张可手算的 9 单 CSV 从预览、字段映射、导入到分析重放，初审六个失败样例、独立复核五个分母变体，共归纳为三个根因：

- **比较期间被截断。** “2026年第一季度对比2026年2月净收入”只查询第一季度；完整日期范围对比月份则只保留日期范围。用户得到的是带完整证据的错误任务答案。
- **问题和界面口径冲突。** 界面确认原订单日，问题却写“按退款发生日”，仍返回订单日口径的 30 元。夹具中发生日口径为 120 元；反向冲突同样存在。
- **不支持的分母被替换。** “退款金额占已收款比例”和“退款金额占收入比例”被自动变为退款金额 / 毛收入，返回 34.29%，尽管没有已收款字段，也未明确收入定义。

独立复核进一步发现：第一次修复只检查标准分母前缀，仍把“毛收入减退款金额后的比例”“毛收入乘2的比例”“毛收入中线上部分的比例”当作标准毛收入分母。空格或逗号后的剩余条件也曾被截断。保留这一中间失败版本，避免把第一次通过回归表述为问题已经完整解决。

## 2. 比较了什么方案，为什么这样选

**计算方案：任意 Text-to-SQL、受约束查询工具、通用 BI。** 本版延续 `query_orders(period, dimension, channel)`：指标和 SQL 由应用定义，用户值参数化绑定，并保留只读约束。它能用一张订单表独立核对六项指标；开放 SQL 或扩成通用 BI 会增加口径、执行和解释范围。此选择有功能覆盖的代价，不声称已经验证优于模型方案。

**混合期间：扩展通用日期解析，或者先要求统一输入。** 本轮选择先澄清，明确提示改为两个带年份月份，或一组起止日期。原因是本版只承诺有限期间语法；已有两个明确月份比较保留。未实现所有季度、月份和多日期混合比较。

**口径冲突：问题覆盖界面、界面覆盖问题，或者要求统一。** 本轮选择冲突时零查询、无报告，让用户统一后重提。退款金额 30 元和 120 元都可能在各自口径下正确，系统不能替用户决定日期归属。

**新分母：自动代换、临时扩指标，或者明确不支持。** 本轮选择严格限制两种分母，并对显式未知分母澄清。不将“收入”自动解释为毛收入，也不把缺失的“已收款”当作已有字段。分母表达式采用完整匹配，允许“的比例是多少”等标准收尾；剩余运算和条件不因标准字段前缀而被丢弃。代价是更复杂的复合句可能需要改写，不宣称通用自然语言理解。

以上为实现中的方案分析，尚未做候选方案的真实模型性能、用户偏好或成本对照实验。

## 3. 具体改了什么

- `analytics.py` 在期间解析前检查混合日期粒度，防止单分支丢掉另一段比较条件。
- 增加问题与确认口径的一致性检查，冲突时返回 `contract` 澄清，执行查询数为 0。
- 在退款比例识别阶段完整检查显式分母，含空格、换行及逗号后的表达式；仅接受已支持的指标契约与合理的语气收尾。
- 在独立手算回归中增加三个根因、完整分母与正常口径控制测试；固定任务集由 10 个扩展为 24 个，包含标准分母的语气及空格正控。
- 冻结修改前解析与导入代码、保存文件哈希，用同组任务实跑前后结果；没有事后编写“修复前数字”。

## 4. 如何验证，实际结果怎样

可复现命令（Python 3.10+、标准库、本机执行）：

```powershell
python verification/replay_20261019.py --baseline
python verification/replay_20261019.py --first-fix
python verification/replay_20261019.py
python evaluate.py
python evaluate_tasks.py
```

结果及解释：

- **22 个自建验收任务：11/22 → 17/22 → 22/22。** 三个冻结/当前版本运行同组任务；第一次修复仍有五个运算/条件分母失败，最终 11 个失败样例从 0/11 变为 11/11；五个已修复控制项、六个正常任务保持通过。不能将这组针对性任务的通过率表述为真实用户问题准确率提升。
- **当前 CSV v2 工程回归 90/90，历史 v1 回归 72/72。** 合计 162 项。历史模型协议桩、旧 SQL 守卫等单独归类，不作为 v2 业务效果。
- **固定 CSV 业务任务 24/24。** 检查问题理解、工具参数、数字和引用；任务与工程回归、冻结重放存在重叠，不应相加当作独立样本量。
- **浏览器原工作流 12/12、本轮专项 9/9。** 实际上传、映射和导入同一 9 单 CSV，复核冲突时零查询、用户修改归属后退款 120 元、混合期间及错误分母澄清、多个指定渠道不截断、正常渠道净收入 230 元；补验算式分母先澄清与标准“的比例是多少”仍返回 12/35。未出现 JavaScript 运行错误。属于本机自动化验收，不是九位用户试用。
- 外部模型调用 0；真实用户测试未开展。没有人效、留存、业务收入或模型准确率结果。
