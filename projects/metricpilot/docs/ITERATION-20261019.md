# MetricPilot：问题、取舍与验证记录（2026-10-19）

本轮从代码审阅与自建验收任务中定位混合期间、退款日期归属和分母替换三类问题，比较方案后修复，并保留冻结版本与同题回放结果。本版采用规则解析和受约束计算。

## 1. 从什么问题出发

原先固定合成数据只能展示分析流程，使用者不能放入自己的订单表。10 月 18 日的 CSV v2 已加入导入、映射、数据质量检查、退款口径、查询证据与报告导出。本轮在这些既有功能上改进口径一致性。

10 月 19 日先重验旧审阅的净收入分母、多渠道、多产品、双季度及多主指标五类问题。新版均已进入澄清，说明旧审阅结论不应直接套用到 v2。随后用同一张可手算的 9 单 CSV 从预览、字段映射、导入到分析重放，初审六个失败样例、独立复核五个分母变体，共归纳为三个根因：

- **比较期间被截断。** “2026年第一季度对比2026年2月净收入”只查询第一季度；完整日期范围对比月份则只保留日期范围。用户得到的是带完整证据的错误任务答案。
- **问题和界面口径冲突。** 界面确认原订单日，问题却写“按退款发生日”，仍返回订单日口径的 30 元。夹具中发生日口径为 120 元；反向冲突同样存在。
- **不支持的分母被替换。** “退款金额占已收款比例”和“退款金额占收入比例”被自动变为退款金额 / 毛收入，返回 34.29%，尽管没有已收款字段，也未明确收入定义。

独立复核进一步发现：第一次修复只检查标准分母前缀，仍把“毛收入减退款金额后的比例”“毛收入乘2的比例”“毛收入中线上部分的比例”当作标准毛收入分母。空格或逗号后的剩余条件也曾被截断。保留这一中间失败版本，避免把第一次通过回归表述为问题已经完整解决。

## 2. 比较了什么方案，为什么这样选

**计算方案：任意 Text-to-SQL、受约束查询工具、通用 BI。** 本版延续 `query_orders(period, dimension, channel)`：指标和 SQL 由应用定义，用户值参数化绑定，并保留只读约束。它能用一张订单表独立核对六项指标；开放 SQL 或扩成通用 BI 会增加口径、执行和解释范围。首版以有限指标换取计算条件明确和结果可复核。

**混合期间：扩展通用日期解析，或者先要求统一输入。** 本轮选择先澄清，明确提示改为两个带年份月份，或一组起止日期。原因是本版只承诺有限期间语法；已有两个明确月份比较保留。未实现所有季度、月份和多日期混合比较。

**口径冲突：问题覆盖界面、界面覆盖问题，或者要求统一。** 本轮选择冲突时零查询、无报告，让用户统一后重提。退款金额 30 元和 120 元都可能在各自口径下正确，系统不能替用户决定日期归属。

**新分母：自动代换、临时扩指标，或者明确不支持。** 本轮选择严格限制两种分母，并对显式未知分母澄清。不将“收入”自动解释为毛收入，也不把缺失的“已收款”当作已有字段。分母表达式采用完整匹配，允许“的比例是多少”等标准收尾；剩余运算和条件不因标准字段前缀而被丢弃。复杂复合句通过澄清引导用户重新确认条件。

## 3. 具体改了什么

- `analytics.py` 在期间解析前检查混合日期粒度，防止单分支丢掉另一段比较条件。
- 增加问题与确认口径的一致性检查，冲突时返回 `contract` 澄清，执行查询数为 0。
- 在退款比例识别阶段完整检查显式分母，含空格、换行及逗号后的表达式；仅接受已支持的指标契约与合理的语气收尾。
- 在独立手算回归中增加三个根因、完整分母与正常口径控制测试；固定任务集由 10 个扩展为 24 个，包含标准分母的语气及空格正控。
- 冻结修改前解析与导入代码、保存文件哈希，用同组任务实跑前后结果。

## 4. 如何验证，实际结果怎样

可复现命令（Python 3.10+、标准库、本机执行）：

```powershell
python verification/replay_20261019.py --baseline
python verification/replay_20261019.py --first-fix
python verification/replay_20261019.py
python evaluate.py
python evaluate_tasks.py
```

结果及解释：

- **22 个自建验收任务：11/22 → 17/22 → 22/22。** 三个冻结/当前版本运行同组任务；第一次修复仍有五个运算/条件分母失败，最终 11 个失败样例从 0/11 变为 11/11；五个已修复控制项、六个正常任务保持通过。该组任务用于固定已知输入的计算与流程回归。

- **固定 CSV 业务任务 24/24。** 检查问题理解、工具参数、数字和引用；任务与工程回归、冻结重放存在重叠，按各自套件分别统计。

## 5. 产品范围与下一步验证

当前支持单张订单表中的收入、渠道与退款统计，规则解析负责识别期间、指标和渠道，并在口径冲突时澄清。商品明细、多币种、分次退款与利润核算需扩展数据结构和指标定义。

下一步邀请使用订单导出表的运营或产品人员，拿脱敏 CSV 完成收入概览、渠道比较和退款分析三项任务。记录完成率、每任务用时、澄清轮数、错误口径、结果复核和导出是否有用，并让用户复述分母及日期归属。

如接入真实模型，冻结同一任务及夹具，分别验证解析、工具参数、数字、引用、耗时与实际 usage。先确定模型是否改善同义改写覆盖，再决定是否替代规则解析。
