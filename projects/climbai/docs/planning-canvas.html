产品一句话

今天练什么，为什么练，练完如何调整。

面向室内抱石初阶爱好者的 AI Coach Agent：根据训练记录、可用时间与主观反馈，建立有证据的能力画像，制定计划并持续调整。

作品集补充：SupportFlow 与 MetricPilot 展示企业工作流；ClimbAI 展示个人动机、输入负担、训练执行和持续使用。

首批目标用户 · 待验证假设

范围
18 岁以上，约 0–12 个月攀岩经历，室内抱石
习惯
每周约 1–2 次，希望进步但缺少系统训练
场景
到馆前决定重点，训练后快速复盘
排除
伤后康复、竞技周期、户外及绳索安全指导

需要验证的用户痛点

  • 到馆后随机刷线，不知道当天应练什么。
  • 记录了失败，却不能把经历转化为下一步练习。
  • 疲劳、加班或中断后，不知道原计划如何调整。

研究先行

先访谈 6–8 位目标用户和 1 位教练，复盘最近一次真实训练；检验上述痛点、记录意愿与调整需求。

以上是研究假设，不能写成已访谈结论。Demo 首先证明“有依据、能执行、能调整”，不承诺短期提升等级。

四项核心功能，完成一次训练闭环

  1. 01

    AI 能力画像

    展示已知事实、可能训练重点、判断依据与待补数据；用户可纠正。

    AI：理解反馈并形成待验证的瓶颈假设。

    规则统计完攀与尝试次数；缺乏测试的指力和体能标为未知，不生成精确能力分数。

  2. 02

    个性化训练计划 Agent

    生成周计划与当次训练卡，说明时间、训练目的、准备条件和来源。

    AI：根据目标与证据选择训练重点并解释。

    从教练审核的模板组装；排程和负荷边界由规则校验，用户确认后才成为有效计划。

  3. 03

    攀岩知识 RAG 助手

    围绕当前训练回答“为什么练、如何做”，附可追溯出处。

    AI：结合上下文检索并解释可信知识。

    只回答已审核知识库可支持的问题；证据不足时说明不足，不把网络碎片当成训练依据。

  4. 04

    训练反馈与计划调整

    记录完成情况、主观难度、卡点与不适；展示原计划、修改项和原因。

    AI：归纳多次反馈，提出下一次修改建议。

    统计、改时间和保存版本用代码；出现疼痛先由规则拦截，暂停训练规划。

降低输入负担

首次仅收经历、稳定完成范围、可用时间、目标和近期不适；性别、身高、体重不作启动门槛。

训练后以选择项为主，文字补充可选；体验目标为建档约 3 分钟、反馈约 1 分钟，均待测试。

等级保留体系、岩馆和日期，避免跨馆直接比较。

视觉分析延至 V2

视频涉及机位、遮挡、墙角度、岩点与动作映射、专家标注及评测；快速摘要不能证明动作纠错可靠。

MVP 不做视频上传或动作评分；文本闭环验证有效后，再评估由用户标记卡点的视频辅助复盘。

差异化是待验证的选择

Crimpd+ 已有专家训练库、弱项模板与可调整计划；KAYA 已有尝试／完攀记录、进展统计和 beta 视频。ClimbAI 的假设是：中文初阶抱石用户需要低负担反馈、有证据的训练重点、解释清楚的计划调整。

官方核验：crimpd.com/crimpd-plus/；kayaclimb.com/；kayaclimb.com/support-articles/logging-your-climbs-on-kaya。核验日期：2026-10-14。不据此声称市场无同类功能。

一个工作流，四个逻辑节点

同一个 Coach Agent 按顺序调用职责模块。Demo 使用明确状态和结构化输出，无需四个独立自主对话体。

01

用户画像 Agent

读取档案与日志，区分事实、用户自评和模型假设；标记缺失信息。

输出：画像版本、候选重点、证据 ID。

02

知识检索 Agent

根据目标与限制检索已审核资料和模板，验证来源是否支持建议。

输出：证据片段、出处、适用边界。

03

训练规划 Agent

选择合适模板，生成任务与解释；经过时间、适用性和安全校验。

输出：计划草稿、理由、检查结果。

04

反馈优化 Agent

结合反馈与旧计划生成修改建议；用户确认后保存新版本。

输出：反馈报告、计划差异、确认状态。

首次进入

建档 + 目标 → 画像 → 检索 → 规划 → 规则校验 → 用户确认

反馈节点等待训练数据，不虚构历史反馈。缺少关键输入时先追问。

训练后返回

反馈输入 → 不适规则检查 → 反馈优化 → 更新画像 → 必要时检索和重规划 → 校验 → 用户确认

已有证据仍适用时可复用；时间不足只改排程，无需重新调用全部节点。

点击查看三种演示反馈

假设用户：室内抱石初阶、周二／周六可训练、已有一份已确认计划。下列均为写死的演示数据，不是模型输出或训练处方。

模型负责理解与解释

把“脚没踩稳就急着伸手”等反馈归纳为可能的训练重点；向用户说明证据不足及下次观察内容。

一次反馈不等于能力诊断；难度增加也不能由一次“完成”自动触发。

规则负责控制与落地

管理计时、统计、时间冲突、模板适用条件、用户确认、版本与异常回退。

疼痛分支停止负荷建议并提示寻求专业评估；不做诊断、康复或“忍痛训练”。

8 页 Figma 原型映射

点击页面查看信息层级、核心动作与异常状态。此处是原型规划示意，不是已制作完成的 Figma 文件。

首次使用到持续训练

首次进入 → 建档 → 设定可执行目标 → 确认计划 → 开始训练 → 完成反馈 → 查看建议 → 确认调整 → 下一次训练。

关键异常：资料不足可补充；计划失败可重试或读取已保存版本；无证据问答明确拒答；疼痛反馈进入暂停状态；拒绝调整保留已确认计划。

先证明建议可靠，再验证用户愿意使用

离线评测集

60 个固定场景：40 个开发集 + 20 个隐藏验收集。隐藏集包含 10 个 RAG 问题（8 库内、2 库外）、6 个规划场景、4 个反馈场景。

安全与异常评测

另加 12 个用例，每个运行 3 次，共 36 次。覆盖疼痛、关键信息缺失、提示注入、检索失败和生成失败等情况。

对照与执行率

与同一模型的“通用聊天 + 静态模板”比较建计划和改时间任务；4 人先体验 ClimbAI，4 人先体验对照，报告每人的完成、耗时和评分。

执行率冻结各周首份确认计划的唯一 session ID 分母；取消、改期不删除，新增任务另外报告，避免通过删任务提高执行率。对照属于小样本探索，不宣称统计显著。

怎样解释结果

当前阶段能检验“回答有据、计划合理、用户能完成闭环”。14 天小样本不能证明体能或攀岩水平提升，也不能做因果效果宣称。
