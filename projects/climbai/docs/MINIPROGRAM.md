# ClimbAI 微信小程序迁移建议

记录日期：2026-10-15。本文件是基于当前 React / FastAPI 实现的迁移建议，尚未创建小程序应用、完成真机验证或提交审核。

## 结论与首版范围

技术上可以迁移。建议保留知识库、引用契约、计划版本和服务端业务规则，使用 Taro React 实现小程序界面。先做今日安排、快捷训练记录、知识问答和历史记录四个入口，验证到馆时是否方便使用，再扩展完整画像和周计划。

当前 React 页面包含浏览器 DOM、hash 路由、localStorage、fetch 和 Blob 下载，迁移时需要分别适配组件、页面路由、本地存储、网络请求和导出。现有页面不能直接作为原生小程序界面使用。Taro 官方说明支持 React 和微信小程序，同时列明与 Web 的组件、路由和 API 差异。

## 可以复用的部分

- backend/knowledge.json 的知识内容、关键词、适用条件和来源元数据。
- FastAPI 的档案、计划、记录、反馈及知识接口，以及 SQLite 中的版本化数据结构。
- TypeScript 数据契约和纯业务计算逻辑；浏览器依赖应放入可替换的适配层。
- 明确标记的离线规则模式，用于无模型密钥的流程验证。

## 上线前需要补齐的部分

1. 账号与会话：当前匿名浏览器 UUID 是演示身份方案。正式小程序需要服务端验证登录凭证，并以服务端身份完成工作区授权；不能直接信任客户端任意传入的会话 ID。
2. 服务部署：当前 GitHub Pages 只提供静态网页。联网小程序需要可访问的 API。普通 wx.request 路径要求配置 HTTPS 通讯域名；微信云托管则有自己的调用方式。AppSecret 和模型密钥继续只保存在服务端。
3. 数据管理：支持本地草稿、网络失败后重试、重复提交保护、跨设备记录归属，以及导出和删除。迁移时保留现有计划版本冲突检查。
4. 发布准备：注册合适的小程序主体与 AppID，在对应后台完成类目、服务配置、隐私声明、体验测试和审核流程；具体发布能力以所选主体的实际后台为准。

## 为什么不默认用 web-view 套用现有网页

微信官方 web-view 文档明确说明个人类型小程序暂不支持该组件，其他网页还需要配置业务域名。因此不把网页套壳作为个人项目的默认方案。采用原生小程序组件或 Taro 迁移，能直接适配到馆记录和返回页面时的状态保存。

## 建议的第一条验收路线

在真机打开 → 查看知识主题并核查来源 → 保存一次模拟训练记录 → 离开后重新进入 → 找回记录 → 查看当前计划并确认一次修改。

同时检查弱网失败、取消修改、旧计划版本、数据删除和未登录访问。知识检索的固定用例可以复用，但网页测试通过不能替代小程序真机测试。小程序迁移也不自动证明真实模型效果或训练成效。
