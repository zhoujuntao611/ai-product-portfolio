# ClimbAI：从训练记录到下一次安排

ClimbAI 是面向室内抱石初阶成年用户的 ToC AI Coach 产品作品。它围绕“今天练什么、为什么这样安排、练完如何调整”设计一个可追溯的训练闭环。

当前交付由 AI 协作制作，包含可操作前端、可运行后端、可配置模型适配、产品文档与工程验证。在线版本使用明确标识的本地演示规则。用户洞察来自产品假设，真实访谈、教练审核、模型业务效果与训练成效仍待验证。

## 1. 为什么补充这个项目

SupportFlow 展示知识工作与人工审核，MetricPilot 展示统计工具和数据追溯。ClimbAI 补充消费端的首次体验、输入负担、个性化、信任建立和持续使用设计。

该项目的价值判断是：帮助用户把零散训练经历变成下一次可执行的安排，是否比单纯记录或通用聊天更有用。

## 2. 场景与待验证问题

初阶爱好者到馆后随机刷线，遇到失败后难以区分技术问题与时间、疲劳等因素；通用计划也可能与个人时间和器材不符。以上是研究假设，尚无真实访谈结论。

首批招募范围为成年室内抱石爱好者；不覆盖竞赛周期、绳索安全教学和伤后康复。体验围绕一个主要目标和一周计划，降低首次使用成本。

## 3. 已核验竞品与差异化假设

[Crimpd+](https://www.crimpd.com/crimpd-plus/)已经支持专家训练库、弱项模板与计划调整。[KAYA](https://kayaclimb.com/support-articles/logging-your-climbs-on-kaya)已经支持尝试与完攀记录。因此不能把“竞品没有训练计划”作为市场机会。

ClimbAI 选择中文初阶用户的低负担反馈、有证据的训练重点和可解释调整作为待验证差异化。

## 4. 四个产品决策

### 画像保留不确定性

用户自报的等级或失败原因不能直接转换为科学力量评分。画像分开显示事实、自评、假设和证据充分度，并允许纠正；缺乏数据的能力保持未知。

### 训练卡优先于聊天入口

首页突出下一次行动，知识问答围绕当前训练提供解释。建档只收必要信息，反馈以选择项为主，文字可选。

### 模型与规则各自处理适合的任务

模型负责语义归纳、综合约束与解释；代码处理时长、统计、版本、引用和状态检查。四个逻辑节点组成一个受控工作流，反馈后才更新画像与计划。

### 调整可以是保持计划

没有新证据时不为了展示“智能”强行修改计划。用户可以接受建议或保持原计划，两种决定都可完成反馈闭环。疼痛反馈先暂停相关任务。

## 5. 工程落地

- React 前端支持八个视图，以及浏览器本地持久化的演示模式。
- FastAPI 后端提供档案、计划、训练、反馈、知识、历史和导出接口。
- SQLite 保存原始记录与版本；知识检索独立管理。
- Coach 工作流执行画像、检索、规划和反馈逻辑；模型配置仅在服务端保存。
- 在线 GitHub Pages 演示可以直接体验；Pages 不运行 Python 后端。

本地演示采用规则和示例知识，真实模型适配需要服务端配置。无密钥时不将规则输出称为真实模型生成。

## 6. 如何验证

工程测试验证身份隔离、版本冲突、疼痛分支、时长约束、引用、异常和数据操作。浏览器检查验证关键交互、桌面与手机布局。结果只对应列出的场景。

下一步用户研究：6–8 人访谈，8 人的任务比较及 14 天探索性试用。使用相同模型的通用聊天和静态计划作为对照，记录实际任务完成、反馈提交与满意度。小样本不能证明攀爬水平提升或效果因果关系。
