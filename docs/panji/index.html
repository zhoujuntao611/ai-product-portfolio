攀迹

接到下一次的行动。

选择岩馆、记录线路尝试、回看视频，再将复盘中的建议变成下次目标。以可运行的训练闭环，探索 AI 在日常攀岩记录中的位置。

01 / 问题与范围

记录以后，下次怎样继续？

我从一个训练场景出发：记下去哪个馆、练了什么之后，如何找到某条线路之前的尝试，并知道下次继续做什么？这个需求仍需要更多用户研究验证，所以先把记录、回看、复盘与目标核对连成可运行流程。

  1. 01选馆与记录

    最近岩馆、复用安排、连续保存尝试。

  2. 02线路与回看

    明确关联同一线路，跨次查看卡点和视频。

  3. 03复盘与确认

    查看事实摘要，手写或生成文字复盘。

  4. 04下次核对

    确认或修改建议，在下次训练中核对目标。

02 / 关键产品决策

先定义事实，再安排模型的职责。

01

程序计算事实，模型提出建议

完成率的分母是完成与未完成的尝试，未知结果单独保留；不同岩馆的难度体系分别展示。统计摘要和事实观察由程序生成，模型只能原样引用允许的事实，再提出谨慎假设和行动建议。

输出经过结构、固定事实与引用校验；建议需要用户确认或修改后才能成为目标。来源记录变化后，旧复盘失效，避免过期建议继续被当作当前依据。

02

用确认与后续入口连接 AI 输出

调用前展示发送范围并取得独立授权，备注默认不发送，视频不发送给模型。生成后的建议有确认和修改入口，下一次训练中可以核对，避免复盘停留在一段文字。

03

在免费资源约束下保留核心记录能力

训练记录可存云端，视频及其关联保存在当前设备，并说明换机和清缓存可能丢失视频。AI 达到限额或资源核对失败时暂停生成，用户仍可记录训练、查看摘要、手写复盘和导出数据。

03 / 根据使用反馈迭代

让连续记录和回看更直接。

手机使用反馈指出视频回看需要多次点击，我把关联视频放进每条线路尝试卡片，点击即可播放；增加连续保存、草稿恢复和选填项折叠，降低记录过程中的打断。

单段视频限制从 60 秒 / 50 MB 放宽到 5 分钟 / 100 MB，同时补充实际大小、时长和保存阶段提示。120 秒 / 80 MB 合成视频在开发者工具中完成导入与播放；原手机视频的编码兼容情况仍需复试。

图片来自开发者工具，训练内容为合成数据；彩条是验收用视频，不代表 AI 动作分析。

04 / 公共数据治理

让选馆资料有出处，也能保留不确定性。

整理 228 个场所、71 个城市 / 地区的部分名录，支持城市、关键词、设施和“已加入”筛选，再直接进入训练记录。保留来源、旧名与开放条件，处理同名分店和资料冲突；相互矛盾的旧地址暂时隐藏，原用户历史记录保留。

名录包含少量人工攀登训练设施。这些数字描述资料快照，不能解释为用户覆盖、全国完整收录或逐家现场确认营业。

05 / 验证与下一步

已跑通开发流程，继续验证真实使用。

原工程已有验收报告记录 176 项自动化检查、14 页原生编译，以及混元 hy3 的 3 类合成场景、7 项开发检查。公开源码移除私有部署处理器及其 2 项专用测试，工程检查范围为 174 项。两种范围分别记录，不把开发验收当作用户测试或建议有效率。

当前为开发预览。完整手机兼容性验收、公开发布和用户效果验证仍待完成。下一轮计划通过真实任务，观察首次训练记录、AI 建议确认或修改，以及下一次训练目标核对，建立明确的样本、时间窗口和分母。

当前 AI 功能是文字复盘，未实现视频动作识别、姿态评分或训练效果预测。
