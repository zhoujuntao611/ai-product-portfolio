从分散的反馈到可执行的维护任务

群聊反馈容易缺少环境和复现步骤。即使 AI 给出代码，开源维护者仍要补齐问题、检查改动、确认测试。Oriel 把原始反馈、补丁和测试记录放在同一流程中，方便逐项审查。

我的工作：负责 Oriel 产品流程、Pico Runtime 与 PicoBench 的设计实现，开发采用 AI 编程协作。当前完成维护者 MVP 与受控评测，真实社区长期试用仍待开展。

  1. 01

    成员留在熟悉的群聊里

    直接提问或描述问题。有效反馈由维护者通过 /issue 沉淀到固定 Gitee 仓库，关联原始消息，重复提交按来源去重。

  2. 02

    修复任务有固定起点

    维护者使用 /fix 触发任务，重新读取 Issue，锁定 Base Revision 和验收命令；同一 Issue 正在处理时，不重复启动修复。

  3. 03

    进度与结果回到原问题

    进度会回复到原来的飞书消息或话题。通过验证后提供候选补丁；失败或受阻时说明原因。

三个决定，控制任务从哪里开始、到哪里结束

维护者确认后再启动任务

普通成员可以反馈问题，创建 Issue 与修复由维护者明确触发。保留确认步骤，关联原消息并去重，避免把未核实的群聊直接变成仓库任务。

补丁离开修复环境后再验一次

修复目录中的测试通过后，从同一基准版本创建干净验证目录，重新应用补丁并运行固定命令，检查结果是否依赖修复时遗留的文件与状态。

交付审查候选，保留人工决定

通过时交付 CANDIDATE.md、补丁、变更文件、退出码与日志；失败或受阻则交付诊断。测试只覆盖已知条件，由维护者审查后决定后续提交与合入。

当前交付物是本地 PR Candidate。实际创建远程 PR、代码审查与合入由维护者完成；候选通过验收，也需要结合测试覆盖范围判断。

稳定请求前缀与估算调用成本

12 个固定用例，各重复 3 次，形成 36 组配对、72 次 Trial、504 次真实 DeepSeek 调用。覆盖对话、长历史与工具链；“稳定前缀”和“逐次扰动前缀”两组分别 36/36 通过。

单位成功任务估算成本的任务聚类配对估计下降 72.08%。它说明该冻结负载下前缀稳定性与缓存成本的关系；对照不是旧产品版本，估算费用也未与实际账单核对。

会话调度的观测值与未通过项

80 组配对、4,160 次真实 Agent Turn，4,158 次满足任务验收。比较全局 FIFO 与会话 Lane，前台 P95 观测值为 13.57 秒 → 11.66 秒；负载是专门构造的队头阻塞场景。

两次回复正常结束但缺少专属标记，未达到预注册的全通过门槛，报告为 claim_eligible: false。因此不据此宣称整体优化通过，也不把这组请求当作真实社区修复率或线上 SLA。

技术与内部实验附录

内部摘要：Schema Token 减少后，任务结果反而退步

PicoBench 固定任务、模型、预算和 Verifier。项目的 Tool Disclosure 实验记录中，Schema Token 减少 92.89%，但通过数从 24 降到 23，延迟也上升，因此不认定为正向优化。成本需要结合验收成功数一起看。

这项结果来自项目内部实验记录，公开源码尚未附原始运行凭证，不能将其作为已独立复现的结果。查看指标与证据范围 ↗

内部摘要：48 个任务与 Skill 人工激活

Runtime 侧的经验复用实验用版本管理、相关性选择、独立验证与失败回退约束候选 Skill。项目记录中的受控 A/B 覆盖 6 类能力、48 个未见及干扰任务，通过数由 15/48 提升至 24/48，增加 18.75 个百分点；该集合中没有原本成功的任务在加入经验后失败。

混淆型负例仍有误选，因此候选保留人工确认。这是固定任务集合上的内部实验摘要，原始凭证尚未公开，不能据此推断真实社区修复成功率。把维护者 Candidate 进一步提炼为 Skill，仍属于后续接入计划。

Runtime 架构与两次标记缺失的含义

Python asyncio 会话级 Lane 保持同会话有序，前后台使用独立并发池；Context 按预算组装，Session、长期记忆与 Skill 分开管理。工具根据读写属性安排执行，安全读取可以并行，写操作保留顺序。CLI、TUI、Gateway、定时任务和飞书共用 Turn 运行时。

调度实验中的两次 marker_missing 均有正常终态、明确回复和完整用量，其中一次达到 512 个输出 Token 上限。这是回复未满足任务要求，不能改写为调度丢失或 Provider 故障；请求执行完整与任务验收通过应分别判断。

跨阶段出错时，怎样定位？

每个 Turn 关联统一 Trace ID，分开记录模型、工具、记忆、任务终态与投递。1,000 组确定性配对中，开启追踪的一侧实现完整链路关联；本地测试的 P95 耗时差为 2.245 毫秒，每个 Turn 约写入 25.1 KiB。这是小规模本地基线的绝对开销估计，不能外推为线上开销比例。

长期记忆和自进化的能力边界

Runtime 提供可选记忆后端接口，当前发布不捆绑 Myna 等外部记忆实现。Myna 自身的 LoCoMo 分数属于独立记忆系统的评测，不能作为 Oriel 的任务准确率。

Evolver 通过预算、候选隔离、封闭测试与人工确认约束搜索。小样本中训练通过率 40%→60%、四题封闭测试 25%→50%，仅用于观察流程，不作为稳定效果结论；与上面的 48 题 Skill A/B 分开看。
